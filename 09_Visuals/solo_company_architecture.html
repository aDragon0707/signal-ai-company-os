一人公司 AI 操作系统架构

一个窗口就是一个员工，一个员工只拿一个 bounded task。上下文不许无限膨胀，交付必须留下 receipt，所有复利回流到本地记忆和公开资产。

Operating Posture CEO = 总架构师 + 总编辑 + 最终签字人
一个窗口，一个角色

不设“全栈万能员工”。前端、后端、审查、增长、写作都拆成独立执行窗口。

60% 上下文闸门

45% 前完成主要执行，55% 开始验证和压缩，60% 前必须交接或退出。

SACP 追责链

每个任务以 receipt 收口：做了什么、证据在哪、谁接手、不能声称什么。

复利回流

文字、代码、销售反馈、平台数据都回写 Obsidian，形成下一轮判断材料。

02

任务窗口生命周期：60% 上下文内收口

每个窗口都不是聊天，是一次可追责事务。到达上下文闸门后，只能验证、压缩、交接，不能继续扩张任务。

TASK / RECEIPT CHAIN
0-8%

读取任务包

目标、范围、允许工具、验收标准、stop rule。只读最小上下文。

8-15%

绑定角色

确认自己是前端、后端、审查、销售还是写作窗口。拒绝跨角色漂移。

15-35%

主要执行

写代码、生成内容、整理名单、做实验。只完成当前 bounded task。

35-45%

局部自检

运行测试、截图、lint、查证据路径、核对平台文案边界。

45-55%

审查与证据

产出 diff、测试结果、截图、manifest、数据反馈或可发送版本。

55-60%

写 Receipt

Goal、Known facts、Evidence、Next action、Do not、Stop if、Residual risk。

60-75%

只许交接

不得继续扩展需求。只能压缩上下文、生成 handoff、指定 next owner。

75%+

强制退出

停止执行，交给新窗口。旧窗口的价值只剩状态压缩和风险提示。

进入条件任务有 owner、边界、验收、工具列表、输入路径。
完成条件有可审查交付物，不是“我觉得完成了”。
追责条件SACP receipt 能说明证据、失败、风险和下一步。
升级条件跨角色、上下文超限、证据缺失、外部承诺，需要 CEO 决策。
03

内容复利矩阵：你写一份，平台各自适配

你的原始思考留在本地，长文进入个人网站，平台账号只做分发和反馈采集。不要让平台反过来控制你的思想结构。

CONTENT / COMPOUND LOOP

每日原始思考

你今天看到什么、判断什么、改变什么。它是所有平台内容和产品任务的源头。

本地思想本体

Obsidian 保存概念、决策、项目复盘、证据索引。个人网站保存可公开长文。

抖音强钩子、短判断、冲突点
B站教程、系统搭建、深度解释
小红书人设、方法、成长记录、可视化笔记

反馈回流

评论、私信、客户线索、收藏、转化、质疑，回到 PMO 和 Obsidian，驱动下一轮项目选择。

核心资产不是平台账号，是你的本地思想库、网站长文、项目证据和可复用工作流。
平台角色平台是适配器和传感器。它们帮你分发，也帮你测量市场的真实反应。
每日闭环原始文字、一个决策、一个任务种子、一个 receipt，明天从反馈继续进化。
04

全栈能力编排：把 skill 拆成工位，不塞进一个窗口

本地 skill 的价值不是“全栈一把梭”，而是组成流水线。每一站只拿当前需要的上下文，产出下一站能接的 receipt。

SKILL / TOOL ORCHESTRATION
CEO Intent原始想法、产品判断、要解决的真实问题。不能直接喂给实现窗口。

Evidence Tail测试失败、截图、用户反馈、代码 diff、平台数据，只保留最新证据。

05

需求澄清到执行：老板对齐工位 + Prompt 厚度

这一层专门解决“我到底想要什么”。先由一个 AI 员工和 CEO 博弈清楚目标、约束和技术路径，再派发给实现窗口。

REQUIREMENT / PROMPT / HANDOFF
CEO Raw Need你的直觉、痛点、商业目标、审美偏好、时间限制。这里允许混乱。
Clarification BargainAI 必须追问：谁用、为什么现在、什么算成功、什么不能做、优先级怎么排。
CEO Sign-off只有经过你确认的 spec、技术路径、角色路由，才能进入执行。
需求澄清员工

01 Boss Interview

用 5 个问题逼近真实需求：用户、结果、约束、证据、截止。不给答案就只做假设表。

Output: clarified intent + assumptions
spec-driven-development

02 Product Spec

把口头需求变成目标、非目标、验收标准、边界、命令、风险和 open questions。

Output: CEO-approved spec
技术路径员工

03 Architecture Path

确定技术路线：前端、后端、数据、状态、权限、部署、测试。先给方案对比。

Output: implementation path + tradeoffs
agent-chassis

04 Agent Routing

决定拆几个窗口：设计、前端、后端、测试、review、security、handoff。每个窗口一票。

Output: worker map + dependency order
Prompt Architect

05 Prompt Pack

为每个窗口生成高质量 prompt：身份、任务、输入、工具、验收、禁止项、交付格式。

Output: role-specific prompt stack
Codex / Claude

06 Bounded Workers

每个 worker 只执行自己的任务包。Claude Code subagent 思路：独立上下文、专门工具、专门 system prompt。

Output: diff / artifact / content
Review Matrix

07 Multi-review

代码 review、设计 review、测试 review、claim review 分开做，不能让实现者审自己。

Output: findings + fix queue
SACP Receipt

08 State Sync

每个窗口结束写 receipt：证据、变更、风险、下一棒。项目状态同步到 dashboard。

Output: handoff + memory update
CEO Learning Loop

09 Engineer Apprentice

把工程痛点转成学习任务：今天为什么卡、读哪个文件、补哪个概念、亲手做哪个小改。

Output: learning receipt
